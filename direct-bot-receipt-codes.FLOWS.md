# Получение и ввод кода без сайта

## Объём

Один исполнитель. Переиспользовать существующие MST-сессии, проверку собственного
контакта, генератор одноразового кода и защищённый ввод кода текущим держателем.
Не менять роли, пилоты, лимиты, сроки, формат OTP, базу данных или адреса webhook.
Не создавать второй хостинг. Внедрение не защищает от полного отказа Timeweb/БД.

## Изменения

- Новое пересылаемое приглашение содержит прямые HTTPS-ссылки MAX/Telegram
  с одним и тем же непрозрачным MST-токеном, а не кодом или телефоном.
- Старое сообщение с mst-ссылкой можно переслать боту. Только доверенные адреса,
  ровно один различный токен; URL не загружается сервером.
- Повреждённая/неоднозначная ссылка даёт понятную ошибку и не проходит в режим
  ввода кода или создания передачи.
- Собственный контакт и совпадение номера обязательны для новых/внешних
  получателей и сотрудников, использующих универсальное приглашение.
- Выбор другого приглашения в том же личном чате выбирает именно его для
  последующего контакта; выдача/повторное подтверждение не происходит при открытии.
- Текущий держатель может явно обновить приглашение из «Моих передач».
  Проверяются личность, текущая роль держателя и версия этапа; чужой/старый callback
  не создаёт сессию. Новый трек не создаётся.
- Приглашения из ЛК получают тот же серверный текст; старый контракт portalUrl
  сохраняется как совместимый, но при доступных ботах пересылаемый текст не
  требует сайта.

## Приёмка

Оба канала и оба типа отправителей: создать трек → прямое приглашение →
получатель подтверждает свой номер → получает код → отправитель выбирает
передачу и вводит код → держатель меняется ровно один раз, трек остаётся прежним.
Сайт во всём этом маршруте не вызывается.

Неверный/чужой/пересланный контакт, устаревшее приглашение/версия, чужой отправитель,
истёкший/неверный/повторный код, повтор webhook и переключение приглашений должны
оставаться безопасными. Старые handoff-коды не аннулируются от одного открытия
ссылки. Недоступный канал не рекламируется. Никаких реальных рассылок, новых
рабочих треков, импортов1С или расширения доступов при тестировании.

Typecheck/build, полный unit, целевые интеграционные тесты и UI-контракт копирования.
Перед публикацией предоставить PR и запросить разрешение на этот новый блок.
