# Статусы в списке «Мои передачи»

База: production `cursor/upload-invite-flow-problems-e22b`, `c9bfa051397715188af75af18d678ae8377926d0` (PR №135).

## Согласованный результат

В MAX и Telegram кнопки списка содержат номер и короткий статус: «В работе», «Ожидает получения», «Завершён». Незавершённые треки идут первыми; завершённые ниже, в том же постраничном списке, без новых фильтров.

## Поведение и границы

- Состояние `completed` даёт «Завершён»; у остальных ожидаемый получатель даёт «Ожидает получения», иначе «В работе». Подтверждённое получение само по себе не завершает трек.
- Сортировка применяется в SQL до пагинации: сначала незавершённые, затем завершённые, внутри прежний порядок по дате создания и id.
- Область «Мои передачи» прежняя: только треки, где пользователь сейчас держатель, либо последний держатель завершённого трека. Чужие/переданные дальше, удалённые и архивные строки не добавляются.
- Завершённый трек открывается существующим read-only callback карточки статуса, с повторной канонической проверкой прав. Действий передачи/OTP/завершения нет.
- Старые action-callback завершённого трека по-прежнему отклоняются. Query/guard, разрешающий изменяющие действия только для незавершённых, не меняется.
- Узкий ответ после оформления конкретной передачи сохраняет прежнюю семантику; завершённые в нём не появляются.
- Не меняются права, backend-статусы, OTP, данные, миграции, окружение, webhook, роли или автодеплой. Не запускаются импорты или реальные доставки.

## Приёмка

Оба бота, сотрудник и внешний профиль: три отметки, подтверждённое получение остаётся «В работе», более новый завершённый ниже активных, смешанная граница страниц без потерь/дублей, завершённый только для чтения, сохранение бизнес-данных, чужой/исторический-only/удалённый/архивный и групповой доступ, stale action-callback. Прежний сценарий явного завершения дополнен проверкой нового списка и карточки.

Проверки запускаются локально на синтетических данных; production-передачи и получатели не имитируются. Развёртывание требует отдельного подтверждения владельца.

## Локальные результаты

- Основной native receipt/status файл: 87/87 PASS, включая 12 новых сценариев списка и дополненную проверку явного завершения для обоих каналов и обоих типов профиля.
- Регрессия создания, matrix и external Telegram: 5/5 PASS отдельным последовательным прогоном.
- Восемь целевых unit-файлов: 60/60 PASS.
- Typecheck, build и whitespace diff-check: PASS. Полный unit/integration всего проекта в этой локальной задаче не перезапускался.
- Реальный сценарий на устройствах остаётся отдельной приёмкой после deploy. У выпуска №135 были повторные 502 в HTTP-проверках из sandbox; эта UI-доработка не объявляет их исправленными.
