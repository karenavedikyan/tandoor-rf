# Статус трека в MAX и Telegram

База: production `cursor/upload-invite-flow-problems-e22b`, merge PR134 `6230c8ae2ad15c4a7f9790d4238595aa2e1fd937`. Отдельная доработка, без PR/merge/deploy.

## Запрос и уточнение владельца

«Важно чтобы было видно у кого трек, статус по нему - а тот кто смотрит уже сам с ним свяжется самостоятельно».

Показываем только имя текущего держателя и актуальное состояние доступного трека. Не добавляем телефоны, messenger-ссылки, отправку сообщений или новые права.

## Поток

- «Статус трека» в главном меню MAX/Telegram открывает постраничный список доступных треков.
- Можно отправить `Статус TT-2026-123`, без отдельного изменяемого черновика поиска.
- Карточка: номер, предмет, актуальное состояние, текущий держатель, ожидаемый получатель при незавершённой передаче, момент запроса и «Обновить статус».
- При ожидании OTP текущий держатель остаётся отправителем. Получение не считается завершением. Завершённый трек показывает последнего держателя; архив обозначается отдельно.
- Никаких изменений бизнес-данных, выдачи OTP, уведомлений или создания черновиков. Навигация только выходит из режима ввода кода, чтобы текст поиска не расходовался как OTP.

## Доступ

- Приватный диалог, актуальная привязка обоих messenger ID и chat ID, активный сотрудник с доступом к разделу или подтверждённый внешний профиль.
- Сотрудники: существующие `canViewOrder`, `mapTransferToOrderDto`, team scope и revoked/participant rules.
- Внешние пользователи: полные статусы только для текущих основных участников, как в `loadExternalPersonOrders` (создатель/держатель/ожидаемый/конечный получатель). История участия сама по себе не раскрывает нынешнее местонахождение и новых участников.
- Удалённые треки не раскрываются; отсутствие и отсутствие доступа дают одинаковый ответ. Каждое обновление заново проверяет права и данные. Карточка защищает читаемую строку от одновременной смены держателя.

## Проверки

Оба канала, сотрудник/внешний профиль, создатель после передачи, конечный и ожидаемый получатели, недоступный и исторический-only трек, актуализация после смены держателя, завершение/архив/удаление, отозванная привязка, групповой чат, team scope, пагинация, неизменность доменных таблиц и существующего черновика, отсутствие телефонов/OTP/уведомлений. Проверка типов, сборка и риск-пропорциональная регрессия меню и native-create.

- Финальные `npm run typecheck`, `npm run build`, `git diff --check`: PASS.
- Полный финальный `npm test`: 1410/1410 PASS.

- Никаких PR/merge/deploy для этой доработки, производственных status-запросов, обновлений ролей/окружения/webhook или реальных доставок не выполнялось. Реальная проверка на устройствах остаётся отдельным шагом после согласованной публикации.
