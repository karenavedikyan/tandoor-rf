# Автоматическая отправка кода подключённому получателю

## Объём

Один исполнитель, основа PR129/275907f. Новые передачи и новые этапы из ЛК,
MAX/Telegram: код доставляется только в действующий подтверждённый личный чат
ожидаемого получателя с разрешёнными уведомлениями. Из двух каналов выбрать один.
Без подтверждённой привязки сохраняется приглашение. Старые треки не сканировать
и не ставить в очередь при запуске, старые уведомления не переотправлять.

## Реализация

- Очередь только нового события этапа, уникальность transfer+handoffVersion.
  Перед генерацией и каждым сообщением повторно проверить получателя, этап,
  архив/удаление, live-привязку и opt-out. Не менять адресата очереди молча.
- Использовать канонический генератор OTP с прежними TTL, проверкой и
  одноразовостью. Не показывать код отправителю/администратору в ответах, истории
  или уведомлениях. OTP в очереди хранить только с аутентифицированным шифрованием.
- Сначала сообщение с предметом/треком и кнопкой обновления, затем только цифры.
  Сохранить прогресс между сообщениями. Повтор ошибки доставки использует тот же
  код, не создаёт новый. После истечения/замещения кода доставку отменить.
- Кнопка нового кода авторизует текущего получателя по live-привязке; чужой
  callback и старый этап отвергать. Действующий код можно повторно показать
  только самому получателю. Обновления ограничить, не сбрасывать защиту OTP.
- Отдельный worker только новой очереди, существующие transports/секреты и
  глобальные delivery-флаги. Не включать прежние отключённые outbox workers:
  это могло бы вызвать старую рассылку.
  Запускать новую очередь после listen независимо от выключенных задач 1С,
  но только при разрешённом external-messenger и глобальной доставке канала.
  В ЛК для держателя показать queued/sent без OTP и оставить приглашение запасным
  действием. При отсутствии доставки/подтверждённой привязки показывать приглашение.
- Только одна новая additive-миграция очереди; production startup применяет
  только её после существующей078 под advisory lock, до listen/worker.
  Проверить контракт и readiness. Не запускать все исторические миграции.

## Приёмка

Сотрудник/внешний отправитель и получатель, оба канала, новое создание и
продолжение того же трека. Подключённому не требуется пересылать приглашение.
Неподключённый получает прежний путь. Успех создания не называется успехом
доставки: отправителю «Код будет отправлен», а не «уже доставлен».

Проверить opt-out/stop/отвязку/смену телефона, неверного/чужого адресата, старый
этап, отмену/архив/удаление, истечение и замену OTP, retry после первого сообщения,
повтор webhook, параллельные workers, обновление кода и лимит, сохранность трека.
Сбой сети после фактической отправки без ответа API может повторить то же
сообщение: не обещать exactly-once внешнего мессенджера.

Полный unit, targeted integration, typecheck/build, upgrade на старой схеме и
production-omit-dev-startup. Тесты только отдельные БД и фиктивные доставки.
Публикацию нового блока согласовать отдельно после проверки; текущие боты не менять.
