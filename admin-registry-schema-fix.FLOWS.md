# Исправление выпуска общего реестра

## Инцидент и границы

После выпуска PR126 пользователь получил серверную ошибку вместо реестра.
Журнал приложения подтверждает ошибки GET /bootstrap, но не раскрывает SQLSTATE.
В запуске контейнера отсутствовал вызов миграции 078, обязательной для нового
реестра и обработчиков создания передач. Это подтверждённый дефект выпуска;
состояние схемы рабочей базы до исправления нужно установить по безопасному
журналу инициализации, не по отсутствию карточек.

Временно развёрнута предыдущая версия приложения. Операции удаления, изменения
треков, импорта 1С, включения подписок и повторной рассылки не выполняются.

## Изменение

Перед открытием порта и запуском фоновых обработчиков выполнить только
идемпотентную, добавочную миграцию 078 под тем же advisory lock, что и штатные
миграции. Проверять фактический контракт таблицы независимо от наличия отметки
в schema_migrations. Не запускать другие ожидающие миграции.

Readiness должен считать отсутствие новой обязательной таблицы неготовностью,
а не выдавать ready. В журнале только факт готовности и applied=true/false,
без персональных данных, SQL, количества рабочих треков и секретов.

## Приёмка

- Обновление базы без таблицы 078 выполняется ровно один раз и сохраняет треки.
- Одновременные и повторные старты безопасны; существующие подписки не меняются.
- Устаревшая отметка о миграции не скрывает отсутствие таблицы.
- Чужие ожидающие миграции не применяются.
- Ошибка подготовки блокирует запуск сервера и обработчиков.
- После подготовки доступны авторизованный bootstrap администратора и создание
  передач; старые уведомления не создаются повторно.
- Проверяется именно node dist/server.js, как в Docker CMD.
- После выпуска сверяются SHA, готовность и безопасный журнал миграции.
  Авторизованную проверку пользователя нельзя заменить одной проверкой health.
