# Переключение ботов на технический домен

Разрешение владельца: переключить MAX и Telegram на технический домен текущего
Timeweb-приложения, сохранив секреты и ожидающие сообщения. Резервного хостинга,
смены DNS сайта и изменения браузерной авторизации нет.

## Исполнение

Операторский шаг запускается внутри production-приложения после открытия порта.
Существующие токены остаются в окружении сервера. Публичного управляющего
endpoint нет. Проверка привязана к production-origin Тандора и фиксированному
техническому домену app258307; тестовый runtime исключён.

Перед изменением каждого канала проверить личность бота, текущую регистрацию
и защиту технического маршрута. Проба маршрута использует недопустимый массив,
который отклоняется до обработки событий: это не искусственное событие бота.
Неверный/отсутствующий секрет должен давать403, действующий секрет с массивом400.

Telegram: менять только известный URL Тандора, сохранять allowed_updates,
max_connections и действующий секрет, drop_pending_updates=false. Пустой,
чужой URL или нестандартный сертификат блокируют изменение
([Telegram setWebhook](https://core.telegram.org/bots/api#setwebhook)).

MAX: сначала создать и проверить новую подписку с действующим секретом и
типами событий, затем удалить только известную старую подписку Тандора.
Протокол и секретный заголовок описаны в
[MAX POST /subscriptions](https://dev.max.ru/docs-api/methods/POST/subscriptions).
Посторонние подписки сохраняются. Пустой список не доказывает отсутствие
другого потребителя; при отсутствии известного адреса изменение блокируется.
Отсутствующий/null список типов событий не заменять недокументированным
значением по умолчанию; в этом случае автоматическое изменение блокируется.
При неудачной проверке новую подписку не объявлять подтверждённой и старую
не удалять.

Повторный запуск с уже установленными адресами не делает mutating API calls.
Сессия PostgreSQL advisory-lock исключает параллельное переключение экземплярами.
Ошибки каналов независимы; они не останавливают приложение. Журнал содержит
только безопасные статусы, без токенов, секретов, сырых ответов и чужих URL.

## Проверки

Тесты: обычное переключение, сохранение параметров/очереди/посторонних подписок,
идемпотентность, пустые/чужие/повреждённые регистрации, неверная личность,
недоступность и неверная защита маршрута, ошибки API, запрет раннего удаления
MAX, production/test-guards. Typecheck, build, unit и затронутые регрессии.

После выпуска: SHA приложения, готовность, журнал отдельно по обоим каналам,
проверка зарегистрированного нового адреса и сохранения защитных заголовков.
Не создавать рабочие треки и не рассылать тестовые сообщения без разрешения.
Пользовательская команда «меню» в обоих ботах остаётся отдельной проверкой.
