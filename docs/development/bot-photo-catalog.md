# Каталог фотографий в MAX и Telegram

Реализация от 14.11.2026 на базе `89fc734c83e0a8fd8885d87e5e536c33162baed1`. Владелец согласовал публикацию этого блока сообщением «публикуй - посмотрим что получилось». Фактические merge SHA и результат ручного deploy фиксируются в PR; этот документ сам по себе не подтверждает живую приёмку.

## Сценарий

- Вход: кнопка «Каталог», точное сообщение «Каталог» или `/catalog`.
- В боте только три раздела: «Входные двери», «Межкомнатные двери», «Фурнитура». Пустые разделы скрыты, модели показываются по восемь.
- Напольные покрытия и погонаж исключены из списков, вариантов и повторной доставки фото по старым кнопкам. Используются исходные категории, их предки и явные типы товара, но не названия моделей; неизвестные и неоднозначные категории скрыты.
- Три навигационных идентификатора существуют только в проекции бота; исходные GUID и записи каталога ЛК не изменяются.
- Группировка использует существующее правило названия и известной РРЦ, но цены не выводятся. Размеры/варианты с собственными фото остаются доступны.
- Выбор модели отправляет одно фото с названием и кнопками вариантов, предыдущего/следующего фото и возврата.
- Публичная проекция содержит только категории, названия и фото. Она не открывает внутренние HTTP-маршруты каталога и не регистрирует пользователя.

## Ограничения

- В список попадают только товары, у которых в текущем снимке есть связанный файл и существующая миниатюра `list` текущего рецепта со статусом `ready`, допустимым размером и совпадающим SHA-256.
- Одна ссылка из 1С не делает модель доступной в боте. Неподготовленные оригиналы пропускаются, даже если исходный файл существует.
- Используется уже сохранённая миниатюра до 640 пикселей, преобразуемая в JPEG в памяти. Это не выдача исходных полноразмерных фотографий.
- Флаг готовности всех миниатюр ЛК не меняется. FTP, массовая подготовка фото, импорты и задания не запускаются.
- Снимок, принадлежность файла SKU и целостность фото проверяются повторно при доставке. Старые кнопки не выбирают товар из нового снимка; при исчезновении фото отправляется сообщение о недоступности.
- Работает только личный диалог. Поиск по названию и выдача альбома в этот блок не включены.
- MAX сохраняет токен загруженного изображения в существующем `reply_extra` для повторной доставки. Авторизация бота не отправляется на upload/CDN-адрес.

## Локальная проверка

Нужен Node.js 22 и отдельная локальная PostgreSQL-база, имя которой содержит `test`. Интеграционный helper полностью пересоздаёт схему этой базы; production URL использовать нельзя.

```sh
npm run typecheck
npm run build
node --import tsx --test --test-concurrency=1 \
  test/unit/tanbot*.test.ts test/unit/tandoor*bot*.test.ts
node --import tsx --test --test-concurrency=1 \
  test/integration/tanbot-catalog.test.ts \
  test/integration/tandoor-independent-bot-main-menu.test.ts \
  test/integration/internal-catalog-thumbnails.test.ts
```

Интеграционные проверки используют синтетические данные и заглушки доставки, запрещают живые HTTP/FTP-обращения. Проверяются фильтрация, привязка SKU/файла, приватность маршрутов, отсутствие изменений прав и черновиков, дедупликация, повтор доставки, смена снимка и отсутствие таблицы миниатюр. Это не проверка реальной доставки через провайдеров.
