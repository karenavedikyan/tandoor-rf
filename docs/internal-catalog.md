# Внутренний каталог продукции из JSON

Отдельный справочный каталог, не замена каталога образцов и не коммерческий импорт. Страница `/internal-catalog`, API `/api/internal-catalog`. Доступ проверяется на сервере тем же действующим правилом, что и чтение раздела «Клиенты». Незарегистрированные, неподтверждённые и не имеющие соответствующих прав пользователи не получают данные.

## Загрузка

Исходный JSON не входит в Git и не помещается в `public`. Предельный размер файла 40 МиБ. Формат: корневой массив товаров с `guid`, `name`, `chapter`, `properties`, `files`; вложенные поля соответствуют проверенной выгрузке 1С. Новые неизвестные поля отклоняются, а не теряются незаметно. Пустая/невалидная выгрузка, дубликаты GUID, противоречивые справочники, абсолютные/опасные пути изображений отклоняются до записи.

После сборки проверка без подключения к БД:

```sh
npm run internal-catalog-import -- /private/path/products.json --dry-run
```

Явная загрузка в предварительно проверенную, разрешённую БД с применённой миграцией 077:

```sh
npm run internal-catalog-import -- /private/path/products.json --apply --expected-sha256 <SHA256-проверенного-файла>
```

По умолчанию работает dry-run. Режим apply требует совпадающий SHA-256. Сам CLI не применяет миграции. Для рабочей БД требуется отдельное согласование публикации и загрузки; этот выпуск подготовлен без публикации.

## Изоляция и целостность

- `internal_catalog_snapshots`: неизменяемые версии с хешем, временем, именем файла и статистикой.
- `internal_catalog_products`: отдельные товары с исходными строками характеристик и производным поисковым индексом.
- Версия записывается атомарно, под отдельной advisory-блокировкой. Повтор того же файла ничего не меняет и не активирует старую версию. Текущей считается последняя новая успешно записанная версия.
- Таблицы `onec_catalog_*`, активная XML-версия, коммерческие данные, распределение образцов и пользовательские треки не обновляются.
- Поиск и карточки используют одну выбранную версию; импорт новой не подменяет сведения в уже открытом списке. Обновление страницы получает последнюю версию.
- Нет HTTP-эндпоинта загрузки, публичного сырого JSON, автоматического удаления товаров или задания FTP.

## Интерфейс

Пункт «Каталог продукции» в существующем меню сотрудников. Поиск по названию, GUID, названиям разделов и характеристикам, включая артикул и бренд. Поиск без учёта регистра, с сопоставлением е/ё и пробелов Unicode, по всем введённым словам; `%` и `_` ищутся как символы, а не SQL-шаблоны. До 160 символов и 8 слов. Фильтры по разделу/GUID и бренду, 24 товара на страницу, сохранение поиска в URL.

Карточки показывают название, бренд, артикул, разделы и состояние файлов фото. Подробная карточка содержит характеристики, отдельно сворачиваемые служебные поля, информацию о файлах изображений, GUID и происхождение данных. Значения выводятся как текст, не HTML. Esc, кнопка закрытия и история браузера возвращают к списку с сохранением условий поиска.

Пустой каталог, отсутствие результатов, недоступность API, запрет доступа и неизвестный товар имеют отдельные состояния. Устаревший ответ поиска не перезаписывает более новый.

## Подготовленное подключение фотографий

Источник выключен по умолчанию. Подготовлен режим `INTERNAL_CATALOG_IMAGE_BACKEND=shared` для среды разработки/проверки; рабочие настройки не менялись. Сначала адаптер ищет готовое превью по точному нормализованному пути в `onec_catalog_image_assets`, читает его через существующий закрытый local/S3-механизм, проверяет SHA-256 и декодирует заново. Только параметризованный SELECT и чтение объектов; без PUT, новых записей изображений или журналов синхронизации.

Если готового превью нет, используется существующее включённое подключение `ONEC_FTP_*`: чтение `/s3/IMG/<нормализованный files[].path>`. Базовый каталог обмена 1С не меняется. Фотокаталог и три точных пути из JSON подтверждены через отдельную консоль Comet. Доступы остаются на сервере; существующее подключение поддерживает plain FTP, добавление TLS этот выпуск не обещает.

Перед скачиванием проверяется объявленный размер: не более 8 МиБ. Фактический размер должен совпасть с объявленным; общий лимит передачи/обработки 15 секунд. Одновременно выполняются два чтения, не более 64 разных запросов ожидают выполнения, очередь ограничена 20 секундами ожидания. Подготовленные превью кэшируются только в памяти процесса: до 64 записей/32 МиБ на пять минут, неудачные чтения на 15 секунд. Запросы одного фото/версии объединяются; ключ изолирован версией и хешем настроек источника. Доступы и ключи не раскрываются. Нет массового скачивания, дискового кэша, импорта, фонового задания и записей синхронизации.

Для отдельной локальной папки сохранён прежний `INTERNAL_CATALOG_IMAGE_SOURCE_DIR`, если режим `shared` не включён. Для подтверждённого FTP-источника отдельный архив и локальное размещение не требуются.

Обложки и галерея используют `/api/internal-catalog/products/:guid/images/:fileGuid?version=:snapshot`. Каждая выдача повторно проверяет действующую сессию и прежние права чтения каталога до обращения к кэшу. Файл должен принадлежать выбранному товару в выбранной версии; путь нельзя передать через URL. Используются существующие безопасное разрешение путей, ограниченное чтение и обработчик превью: по умолчанию до 8 МиБ, 4096 пикселей по стороне, 24 Мп, превью до 1200 пикселей, без увеличения. Превью перекодируется в WebP без исходных метаданных, не записывается на диск и не размещается в public. Защита `no-store` сохраняется, корень и ошибки файловой системы не раскрываются.

При отключённом источнике показана прежняя честная подсказка, отсутствующий/повреждённый файл не ломает товар: вместо картинки выводится сообщение. Фотография открывается крупнее в отдельной вкладке с теми же правами. Данные 1С, XML-каталог и таблицы трекера не изменяются.

Публикация приложения, загрузка JSON в рабочую БД и изменение рабочих настроек источника не выполнялись. Версия фиксирует сопоставление файлов в JSON, но не архивирует исходные байты FTP: изменённое на месте фото может обновиться после истечения кэша.

## Ограничения исходного файла

В проверенном файле 4 696 товаров, 118 разных GUID разделов и 61 непустое значение бренда. У 2 907 товаров указаны 3 770 путей изображений; источник FTP подтверждён выборочно и подготовлен к подключению без публикации. Полнота и декодирование всех 3 770 путей не проверены. Товары без фотографии или с недоступным файлом не получают выдуманных изображений.

Цены/остатки/даты есть лишь у части товаров в виде строковых характеристик. Они не интерпретируются как текущие коммерческие данные; валюта, единицы измерения, склад и актуальность не додумываются. Пустые значения не превращаются в нули. Порядок разделов не используется для восстановления иерархии или товарной группы. Отсутствие флага «сайт Тандор» не меняет доступность товара.

2 972 значения имеют длину ровно 1 024 символа. Это повод проверить полноту выгрузки у 1С-специалиста, не доказательство обрезки. Полученный текст сохраняется полностью, без искусственного продолжения.
