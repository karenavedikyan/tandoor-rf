# R2.3 «Моя работа» — семантика экрана

**Этап:** R2.3 (агрегированная очередь поручений)  
**Не закрывает:** R2 целиком, приёмку ограниченной сводки рекламаций, массовую синхронизацию Bitrix24

## Единая очередь: решение владельца 01.10.2026

- Документы и возвраты отображаются как обычные задачи/пункты чек-листов Битрикс24, без повторного ввода и отдельного процесса в ЛК.
- Отдельное представление документов возможно только как необязательный фильтр той же очереди, если его польза подтверждена.
- Рекламации используют исходные задачи; менеджеру без полного доступа видна только разрешённая опубликованная сводка. Сначала проверяем существующий механизм, затем дорабатываем только недостающее.
- Полные границы и следующий шаг: [план R2](./release-plan.md#r2--моя-работа-и-общий-контекст). Матрица прав не расширяется.

## Источник данных

- Только **серверный кэш** ЛК (`bitrix24_task_cache`, `bitrix24_task_bindings`, чек-листы, сводки).
- При открытии экрана, поиске, фильтрации и пагинации **HTTP к Bitrix24 не выполняется**.
- Кнопка «Обновить данные ЛК» повторно читает кэш через `GET /api/work/tasks`.
- Свежие данные из Bitrix24 — только через существующую ручную синхронизацию в **карточке клиента**.

## Очередь и дедупликация

- Одна строка на пару **`portal_id + task_id`**, даже если задача видна с нескольких карточек клиентов.
- Перед дедупликацией собираются **все** разрешённые связи по scoped-карточкам; фильтр `clientGuid` и поиск учитывают **любую** доступную карточку.
- В ответе — массив **`clients`** (все разрешённые карточки); primary — **минимальный `guid_client`** (стабильный tie-break для ссылок).
- Учитываются только **подтверждённые** привязки (`binding_status = confirmed`) с действующей меткой и подтверждённым объектом; только **настроенный** `portalId` из конфигурации Bitrix24.

## Права

- Матрица доступа **не расширяется** — те же правила, что для блока «Работа» в карточке.
- Доступ к клиенту **≠** полный доступ к задаче.
- **Full:** название, срок, портал, прогресс чек-листа (если снимок достоверен).
- **Summary:** опубликованная сводка + ответственный; без названия задачи, срока, пунктов и прогресса чек-листа.
- Поиск, счётчики и варианты фильтров строятся **только по разрешённым полям** (summary не ищет скрытый `title`).
- Истечение замещения и отзыв доступа проверяются **на каждый запрос** (`loadAccessContext`).
- TTL/верификация portal link из main **не ослабляются**.

## Группы сроков (Europe/Moscow)

| Группа | Правило |
|--------|---------|
| Просрочено | Открытая задача, срок уже прошёл, включая прошедшее время сегодня |
| Сегодня | Открытая, срок в **текущий** день MSK и ещё не прошёл |
| Предстоящие | Открытая, срок **после** сегодня MSK |
| Без срока | Открытая, доступный срок отсутствует; summary с закрытым сроком включается сюда с явным пояснением «Срок: недоступен», без утверждения об отсутствии срока в Б24 |
| Завершённые | `status_label = completed` — **не** считаются просроченными |

Сортировка: просроченные и ближайшие сроки первыми; завершённые по умолчанию **скрыты** (`status=open`).

## Счётчики и фильтры

- Счётчики **всех пяти** групп сроков — по разрешённой выборке с учётом поиска/`clientGuid`/ответственного/`statusLabel`, **без** `status=open` и **без** `deadlineGroup` (chip «Завершённые» и дефолтное скрытие completed на списке счётчики не обнуляют).
- Список по умолчанию: `status=open` (завершённые скрыты); chip «Завершённые» — `deadlineGroup=completed&status=all`.
- Пагинация — **серверная**, после фильтрации и сортировки.
- `loadedAt` — время сборки ответа API; `cacheLatestSyncedAt` — максимальный `synced_at` среди показанных кандидатов кэша.

## Чек-листы и личная отметка

- В списке — только **прогресс** (`listMode`, без `items[]`); раскрытие пунктов — lazy через `GET /api/clients/{guid}/bitrix24/tasks` (кэш/full).
- Summary-задачи **без** индикатора чек-листа.
- `stale` / `partial` / `error` — **не** актуальный прогресс и **не** пустой чек-лист.
- «Связаться с ответственным» — та же запись `bitrix24_task_contact_actions`, что в карточке клиента.
- При отказе доступа очередь очищается, включая варианты фильтров. Исчезновение задачи или переход full → summary при раскрытии сбрасывает старые подробности; ошибка повторной загрузки не восстанавливает их.
- Контакты и метаданные прогресса загружаются только для выбранной страницы; `items_json` не читается списком. Лёгкие scoped-метаданные для фильтрации/счётчиков пока обрабатываются на сервере в памяти.

## API

- `GET /api/work/tasks` — список, счётчики, options, метаданные кэша.
- Query: `q`, `clientGuid`, `responsibleBitrixUserId`, `statusLabel`, `deadlineGroup`, `page`, `pageSize`, `status`.

## Навигация

- Раздел **«Моя работа»** в боковом меню (для ролей с доступом к клиентам).
- Переход в карточку: `/clients/{guid}?tab=work&task={taskId}`.
