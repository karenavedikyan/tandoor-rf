# Ручное обновление из 1С с проверкой качества

Реализация подготовлена в ветке `computer/onec-manual-quality-update`. Она заменяет производственный ручной путь существующей кнопки на загрузку 12 файлов с сохранением исходных строк и замечаниями. На рабочем сайте эта версия не опубликована; рабочий импорт и расписания в рамках разработки не запускались.

## Поведение

- **Источник:** четыре клиентских файла, четыре файла продаж/возвратов и четыре товарных файла. Формат JSON не меняется, manifest не требуется. Каждый найденный файл повторно читается по тому же пути, затем проверяется отпечаток всего комплекта перед применением.
- **Сохранение:** все исходные байты и строки, в том числе одинаковые и конфликтующие дубли, сохраняются в отдельном журнале. Некорректная структура отдельной строки становится замечанием; повреждение JSON или отсутствие обязательного файла останавливает обновление.
- **Карточки:** обновляются непротиворечивые поля существующих GUID. Для конфликтующего поля не выбирается произвольно первый или последний вариант. Отсутствие записи не удаляет ранее загруженный объект.
- **Сохранность доступа:** назначения, родительские связи и состав, влияющий на доступ, не переписываются автоматически. Отличия источника отмечаются как требующие проверки; новые записи не получают произвольных назначений. Профили, телефоны, бот-привязки, история, вложения и треки этим импортом не изменяются.
- **Продажи:** исходные операции сохраняются отдельно от расчётной проекции. Точные повторы сводного ключа не увеличивают оборот; конфликтующие сводные значения не перезаписывают прежние. Законные повторные строки возвратов сохраняются. Отсутствующие строки месячной детализации удерживаются до отдельного определения семантики удаления.
- **Каталог:** поддерживаются `guid_group` и `name_group`, сохраняются товары, группы, цены и остатки. В карточке доступны исходные строки цен и остатков; отсутствие значения не заменяется нулём. Существующее ограничение доступа к внутреннему каталогу сохраняется.

## Проверка пользователем

- **Красная отметка:** в обычном, сгруппированном, мобильном и полноэкранном списке, в карточках и каталоге. Отметка открывает текст причины; для конфликтов показываются разрешённые исходные поля, не назначения и не закрытые связи.
- **Фильтр:** «Требуют проверки» использует существующую область доступа до подсчёта и пагинации. Сгруппированный список учитывает также замечания доступных юрлиц холдинга.
- **Повторная загрузка:** снимаются устранённые замечания конкретного файла/объекта. Отсутствующий в новом файле объект сохраняет прежнюю диагностику; наличие его продаж не стирает ошибку клиентского справочника.
- **Администратор:** существующая кнопка запускает задачу, показывает результат и исходное число строк каждого файла. Построчный отчёт с пагинацией включает также сотрудников, группы и строки без корректного GUID.

## Техническое устройство

- **Миграция:** `083_onec_manual_exchange.sql`, только новые таблицы исходных данных, комплектов, замечаний и указателей активных версий. Старые бизнес-таблицы не очищаются.
- **Атомарность:** проекции клиентов, продаж, каталога, исходные файлы и замечания применяются одной транзакцией. Ошибка до commit откатывает изменения; неопределённый commit блокирует последующий apply для проверки оператором.
- **Совместимость:** используются действующие очередь, worker, CSRF и серверная проверка администратора. Старые явно переданные тестовые наборы четырёх файлов и отдельная реализация ночного обмена не заменяются этим ручным путём; расписания не включаются.
- **Повтор:** тот же активный отпечаток возвращает «Нет изменений». Ранее использованный комплект может быть повторно активирован без размножения исходных строк.

## Проверки и границы выпуска

Проверки выполняются только на локальных базах с именами, заканчивающимися на `_test`. Интеграционные тесты используют настоящий PostgreSQL, включая реальную HTTP-постановку задания и worker с локальными байтами вместо FTP. Отдельный сквозной браузерный тест использует настоящий API и БД, кнопку обновления, отчёт, фильтр и повторное исправление; тесты с подменой API явно названы отдельно.

Проверяются повреждённый комплект, сырые `null`/числа/массивы, конфликтующие GUID, повтор без изменений, возврат к предыдущему комплекту, технический rollback, параллельный запуск, сохранность назначений, запрет чужой диагностики, частичная месячная детализация, HTML в значениях и экран 375 px. Присланный комплект из 12 файлов дополнительно импортируется в отдельную локальную тестовую БД.

### Результаты локальной проверки

- **Типы и сборка:** `npm run typecheck` и `npm run build` завершились успешно.
- **Полный unit regression:** 1447 тестов, 1447 успешно, без пропусков и ошибок. После последней защитной правки проверки блокировки применения повторно пройдены typecheck и затронутые интеграционные сценарии.
- **Интеграция:** совместный прогон ручного обмена и API каталога завершился с 23 успешными тестами. Финальный повтор 9 тестов ручного обмена, включая присланный комплект, также прошёл без ошибок.
- **Браузер с подменой API:** совместный прогон кнопки, каталога и карточки завершился с 14 успешными тестами. Финальный повтор 4 затронутых проверок кнопки и карточки прошёл без ошибок.
- **Сквозной браузер:** 1 успешный сценарий без подмены API, с локальным PostgreSQL, двумя запусками через кнопку, отчётом, фильтром, снятием исправленных замечаний и экраном 375 px. Красные замечания дополнительно проверены визуально в полноэкранном списке и мобильной карточке.

Перед первым рабочим запуском требуется отдельно согласовать публикацию и миграцию, затем подтвердить фактические FTP-пути. Код содержит фиксированный список допустимых имён и каталогов с совместимыми альтернативами; их наличие на рабочем FTP в этой разработке не проверялось.

Без признака готовности единого выпуска со стороны 1С можно подтвердить стабильность байтов при повторном чтении, но нельзя доказать, что все файлы созданы в одну секунду или одну генерацию. Это ограничение явно отражено в результате проверки; формат выгрузки ради его обхода не изменялся.

Полное обнуление периода, удаление исчезнувших объектов и автоматическое переназначение доступа намеренно не реализованы: для них нужны отдельные согласованные правила. Строка без пригодного идентификатора либо без безопасной проекции доступна в административном исходном отчёте, а не превращается в выдуманную бизнес-карточку.
