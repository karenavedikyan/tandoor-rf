# Постоянные миниатюры каталога

## Граница

Только производные фото раздела `/internal-catalog`. Товары, исходные GUID,
группировка размеров, цены/остатки, история и оригинальные фото не изменяются.
Не запускаются импорт 1С, расписания, сообщения или новые фоновые процессы.
Настройки окружения, S3, DNS, webhook и роли не меняются.

В production-проверке 14.11.2026 приложение использовало backend `local`,
`INTERNAL_CATALOG_IMAGE_BACKEND=shared`, без подключённых S3-ключей.
Наличие бакета в аккаунте не означает, что приложение умеет его читать.
Поэтому для небольших производных используется существующий постоянный PostgreSQL,
а не временный диск контейнера. Изображения не делаются публичными.

## Контракт

- Добавочная миграция `085_internal_catalog_thumbnails.sql`, одна новая таблица.
- Ключ: исходный snapshot UUID + нормализованный source path + версия рецепта.
- Один источник, использованный разными SKU, готовится один раз. SKU не объединяются.
- WebP без EXIF, без обрезки/увеличения: `small` до 240px/32KiB,
  `list` до 640px/128KiB, качество 76.
- «Таблица» и лента фото карточки используют `small`; оба карточных режима списка
  используют `list`. Основное фото карточки и увеличение используют прежний маршрут.
- GET `.../images/:fileGuid?version=:snapshot&preview=small|list` проверяет прежний
  admin-доступ, отсутствие employee-preview, принадлежность file GUID товару/снимку.
  Запрос только читает готовые байты и проверяет SHA256; FTP и декодер не вызываются.
  `no-store` сохраняется: отзыв доступа не ослабляется ради браузерного кэша.
- Переключение через `meta.thumbnailsReady` происходит после первого полного прохода
  всех путей снимка, при наличии хотя бы одного готового фото. До этого сохраняется
  прежняя выдача. Отсутствие миграции также не ломает существующий каталог.
- Отсутствующий/повреждённый/превысивший лимиты источник имеет явный результат
  `unavailable`, а не вымышленное фото. В интерфейсе действует прежняя заглушка.
  Временный сетевой сбой не объявляется доказанным отсутствием файла на FTP.

## Выпуск и ручная подготовка

Merge/deploy и production-миграция требуют согласования выпуска этого PR.
Автодеплой остаётся выключенным. Один законченный PR, один ручной deploy.

После согласования:

1. Зафиксировать production SHA, текущий снимок/число товаров и неизменность исходных
   записей; проверить резервную копию БД. Сверить pending migrations: только 085.
2. Выполнить один ручной deploy согласованного SHA и применить только добавочную
   миграцию 085. До подготовки старый механизм фотографий остаётся рабочим.
3. В консоли контейнера: `node dist/cli/internal-catalog-thumbnails.js --max-files=3`.
   Это dry-run: чтение/декодирование источников без записи миниатюр.
4. Небольшой apply: `node dist/cli/internal-catalog-thumbnails.js --apply --max-files=3`.
   Проверить два размера через авторизованный API и независимое подключение к БД.
5. Полный проход:
   `node dist/cli/internal-catalog-thumbnails.js --apply --max-files=10000`.
   При ограничении/прерывании повторить вручную: готовые проверяются и пропускаются.
6. Один отдельный ручной повтор временно недоступных источников:
   `node dist/cli/internal-catalog-thumbnails.js --apply --retry-failed --max-files=10000`.
   Не повторять бесконечно. Сохранить итоговые ready/unavailable/bytes и список
   затронутых товаров для проверки источников.
7. Обновить страницу. Проверить `thumbnailsReady`, реальные URL `preview=small/list`,
   поиск, размеры, detail/увеличение, mobile 375px и desktop 1440px. Сравнить исходные
   GUID/записи и число товаров до/после. Проверить, что выдача миниатюр не обращается
   к FTP; cold/warm измерения делать отдельно, не обещать коэффициент ускорения.

CLI удерживает отдельную advisory lease, использует одно последовательное
FTP-соединение с переподключением после сбоя. Лимиты: 45 минут/запуск,
8GiB полученных исходников, максимум 10000 попыток; не более 256MiB производных
для одного снимка/рецепта. Исходные ограничения байтов/пикселей/форматов сохраняются.
Смена активного снимка останавливает публикацию результатов; миниатюры разных
снимков не смешиваются. Код завершения 2 означает ограниченный проход или наличие
недоступных источников, не успешную подготовку всех фото.

## Откат

Откатить код на предыдущий production SHA. Старый код новую таблицу не использует,
исторические записи/файлы не менялись. Таблицу и готовые миниатюры не удалять.
