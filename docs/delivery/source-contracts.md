## 1. Обмен 1С → FTP → PostgreSQL

### Подтверждено кодом — пути FTP (три уровня, не смешивать)

| Уровень | Значение | Где |
|---------|----------|-----|
| **Базовый каталог** | `ONEC_FTP_BASE_PATH` — **обязательный** env при `ONEC_FTP_ENABLED=true`; **значения по умолчанию в коде нет** | `src/onec-ftp/config.ts` |
| **Относительный путь файла** | `CLIENTS_RELATIVE_PATH = "clients/all_clients.json"` | `src/onec-clients/constants.ts` |
| **Итоговый remote path** | `` `${basePath}/clients/all_clients.json` `` (хвостовые `/` у base обрезаются) | `src/onec-clients/path.ts` → `buildClientsFilePath` |

**Пример:** `ONEC_FTP_BASE_PATH=/LC` → файл **`/LC/clients/all_clients.json`**.  
В `.env.example` указан пример `/LC` — это **не** runtime-default приложения.

| Параметр | Значение | Где |
|----------|----------|-----|
| Транспорт | Plain FTP, read-only CLI | `src/onec-ftp/*` |
| Лимиты | 10 MiB, 50 000 записей, 60 с read deadline | `src/onec-clients/constants.ts` |
| Режим по умолчанию | dry-run | `src/onec-clients/cli-args.ts` |
| Apply | `--apply --expected-sha256 <64 hex>` | `README.md` |
| Журнал | `onec_client_import_runs` | `server/migrations/002_onec_clients.sql` |

### Подтверждено тестами

- Валидация JSON, UUID, дубликатов, BOM
- Импорт apply/dry-run, advisory lock, hash mismatch
- FTP probe mock

### Разрешённая область FTP (v1.1 — политика, не env)

Отдельно от `ONEC_FTP_BASE_PATH` и `CLIENTS_RELATIVE_PATH`. Типичная раскладка при `basePath=/LC`:

| Каталог / файл | Назначение | Статус в ЛК |
|----------------|------------|-------------|
| `/LC/clients/all_clients.json` | Snapshot клиентов | **импорт подключён** (CLI) |
| `/LC/catalog/` | Товарный блок (XML) | **не подключён** (R3.1) |
| Заказы / финансы | O01–O07 и др. | **отдельно согласовать**; не расширять молча |

Текущие файлы и архивы **не смешивать**.

### Требует проверки источника

| Тема | Источник | Статус |
|------|----------|--------|
| Периодичность выгрузки 1С | 1С-специалист | неизвестно |
| 3 824 записи в файле vs 3 808 в БД (28.09) | аудит v1.1 | **повторить сверку** на согласованной среде |
| Структура `Markups`, `Discount`, `DiscountAmount` | R1.1 / 1С | **не в `KNOWN_CLIENT_KEYS`**; объявленные поля не считать полученными до проверки |
| Расширенная карточка (юрлица, ТТ, реквизиты) | 1С готовит | **файл не получен** в репозитории |

## 2. Поля JSON `all_clients.json` (текущий контракт импорта)

### Подтверждено кодом — 8 обязательных ключей

| JSON-ключ | Колонка | Обязательность | API/UI |
|-----------|---------|----------------|--------|
| `guid_client` | `guid_client` PK | да | list + detail |
| `name_client` | `name_client` | да | list + detail |
| `guid_holding` | `guid_holding` | да (пустая строка → NULL) | holding filter |
| `name_holding` | `name_holding` | да | holding.name |
| `guid_manager` | `guid_manager` | да | manager filter |
| `name_manager` | `name_manager` | да | manager.name |
| `address` | `address` | да (пустой → warning) | list + detail |
| `telephone` | `telephone` JSONB | да (пустой → warning) | phones |

### Семантика `guid_client` (v1.1 + R0.2)

- В UI — «клиент» / строка snapshot.
- **Не утверждать** без контракта, что это юрлицо или торговая точка.
- Холдинг в текущем обмене — **атрибут строки**, не нормализованная сущность.

### Игнорируется при импорте

- Любые дополнительные ключи → warning `unknown_field`, **без сохранения** (в т.ч. скидки/наценки до R1.1).

### Планируется в R1.1 (промпт; **не в контракте main**)

| Поле | Область применения | Статус |
|------|-------------------|--------|
| `Discount` | коммерческие условия | ⏸ ждёт R0.2 + примеры |
| `DiscountAmount` | коммерческие условия | ⏸ |
| `Markups` | наценки | ⏸ |

### Не в схеме — нужна новая выгрузка + R1.2

| Группа | Примеры | Прототип |
|--------|---------|----------|
| Реквизиты | INN, KPP, OGRN, legal name, email, region, city, MA | экран 05 |
| Иерархия | холдинг, юрлица, ТТ, места доставки (явные ID) | экран 05 |
| Команда | regional, furniture manager, ROP | экран 04–05 |
| Коммерция | тип клиента, оплата, план, ретро | экран 04–05 |
| Договоры | — | экран 05 |

## 3. Связи сущностей (v1.1)

### Модель данных

| Сущность | Описание | Статус на main |
|----------|----------|----------------|
| Холдинг | = клиент в бизнес-модели v1.1 | атрибут `guid_holding` на строке |
| Юрлицо | отдельная сущность | **нет** |
| Торговая точка | отдельная сущность с ID | **нет** |
| Место доставки | отдельно от ТТ | **нет** |

### Подтверждено кодом

- `users` ↔ `onec_clients`: **нет FK** (migration 001 comment)
- `guid_manager`: UUID менеджера **из 1С**; **не** `users.id`
- БД ЛК: разрешённый кэш, права, аудит — **не** второй справочник CRM

### Запрещено без контракта

- Связи по совпадению `name_*` или `address`
- Фиктивные значения (UI: «Подключение данных не завершено»)
- Адрес доставки → ТТ автоматически

## 4. Auth и область видимости

### Подтверждено кодом

| API | Доступ |
|-----|--------|
| `/api/auth/*`, `/api/profile/self` | активный пользователь |
| `/api/clients/*` | **`requireAdmin`** только |

`?manager=<uuid>` — ручной фильтр администратора, не «моя база».

### Подтверждено тестами

- Все роли кроме `admin` → 403 на `/api/clients`
- 401 без сессии; disabled user не логинится

### Нужно реализовать (R1.3, v1.1)

| Роль | Область (целевая) |
|------|-------------------|
| manager | назначенные клиенты |
| regional_manager | подтверждённая территория |
| rop | своя команда |

Связь аккаунта ЛК с ID сотрудника источника — **без сопоставления только по ФИО**.  
Технический `admin` **не** получает автоматически бизнес-право согласовать витринную скидку.

## 8. Следующий шаг (R0.2)

**Контракт** уточняется по **фактически полученной** структуре обмена и **подтверждённым** сведениям 1С (образцы файлов, спецификация полей, ответы 1С-специалиста).

**Синтетические фикстуры** — только для тестов и валидации парсера; **не доказывают** наличие полей в реальном обмене и **не расширяют** контракт без подтверждения источника.

При недостатке проверенных материалов — **блокер** в `source-contracts.md`, поле остаётся «неизвестно»; контракт **не выдумывать**. **Production FTP/БД не подключать.**
