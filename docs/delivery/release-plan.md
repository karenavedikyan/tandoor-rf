## R1 — «Мои клиенты» (целевой первый полезный релиз)

### Сценарий (из согласованной формулировки задачи)

Сотрудник входит → видит **своих** клиентов → находит клиента → открывает контакт, адрес, условия и ответственных → понимает **актуальность** информации.

### Минимум полезного R1

| Компонент | Статус на main | Категория |
|-----------|----------------|-----------|
| Вход (email/пароль, сессия, rate limit) | Реализовано | подтверждено кодом + тестами |
| Роли в БД (`admin`, `manager`, `regional_manager`, `rop`, …) | Реализовано | подтверждено кодом |
| Профиль (ФИО, email, телефон, роль, статус) | Реализовано | подтверждено кодом + тестами |
| Связь аккаунта ЛК ↔ ID сотрудника 1С | **Отсутствует** | нужно реализовать |
| Область видимости manager / regional / ROP | **Отсутствует** (все не-admin → 403 на клиентов) | нужно реализовать |
| Список клиентов с поиском и фильтрами | Реализовано **только для admin** | частично готово |
| Карточка клиента (контакты, менеджер, холдинг, актуальность) | Частично (8 полей 1С + UI-заглушки) | частично готово |
| Импорт snapshot 1С → PostgreSQL | CLI `--apply`, не cron | подтверждено кодом |
| Отображение времени загрузки записи | `last_imported_at` (МСК) | подтверждено кодом |

### Что возможно на **существующем подтверждённом обмене** (8 полей JSON)

- Идентификатор и название клиента (`guid_client`, `name_client`)
- Холдинг как пара UUID + имя (`guid_holding`, `name_holding`) — **не** отдельная сущность «юрлицо»
- Менеджер из 1С как UUID + имя (`guid_manager`, `name_manager`) — **не** привязан к пользователю ЛК
- Фактический адрес и массив телефонов
- Метка актуальности по времени импорта строки в БД

### Что зависит от **новой выгрузки 1С** (не в текущем контракте)

- Реквизиты (ИНН, КПП, ОГРН, юр. наименование, email, регион, город, MA)
- Коммерческие условия (тип клиента, оплата, скидки, наценки, план, ретро)
- Региональный / фурнитурный менеджер, РОП
- Торговые точки, места доставки, иерархия юрлиц

Дополнительные ключи в JSON сегодня дают **warning** при импорте, но **не сохраняются** (`src/onec-clients/validate.ts`).

### Без чего нельзя выпускать даже ограниченный пилот R1

1. **Модель связи** `users` ↔ `guid_manager` (или иной стабильный ID сотрудника 1С) — согласованная с владельцем и 1С.
2. **Серверная фильтрация** списка/карточки по области видимости роли (не снятие `requireAdmin` «для всех»).
3. **Runbook импорта** на согласованной среде (расписание, мониторинг `onec_client_import_runs`, обработка `running`/ошибок).
4. **Решение по фирменному эталону** (шрифт, прототип) — см. [brand-contract.md](./brand-contract.md).

### За пределами R1 (не блокируют описание R1, но не входят в минимум)

- Каталог, Bitrix-заказы, карты, KPI, глобальный поиск
- Торговые точки как связанная сущность
- Автоматический импорт из UI (сейчас только CLI)
- CRM-функции (создание клиентов, редактирование в 1С из ЛК)

### Принципы данных (из задачи R0.1)

- Холдинг, юрлицо, торговая точка, место доставки — **разные сущности**; связи не выводить по совпадению названий или адресов.
- ЛК — единое окно поверх существующих систем, **не** новая CRM.
