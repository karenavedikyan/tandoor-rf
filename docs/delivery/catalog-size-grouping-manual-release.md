# Группировка размеров: подготовка ручного выпуска

Историческая памятка PR165. Новое согласованное правило «название без размера + цена» и текущие ограничения проверки описаны в `catalog-name-price-grouping.md`; приведённые ниже условия PR165 не являются условиями новой группировки.

Статус: исправление подготовлено к PR; эта памятка не является разрешением на слияние или деплой. Изменения затрагивают только read-only группировку каталога. Миграции и повторный импорт не нужны.

## Объём изменения

- **Идентичность модели:** остаются обязательными исходная связь `СсылкаНаГлавную`, одинаковое название без размера, группа и разделы, выбранный тип цены и одинаковая известная цена. Два разных GUID одного размера не скрываются.
- **Несущественные отличия:** `Тип товара`, `сайт Тандор`, `СсылкаНаГлавнуюNEW` не разделяют размеры. Регистр и пробелы значений нормализуются только для сравнения; исходные значения не переписываются.
- **Уточнение владельца:** legacy-флаг `ВХ. Стеклопакет` не разделяет размеры одной модели. Пример: «Аваллон мет/мет меланж левая», 850×2030 и 950×2030, одна цена. Исходные `да`/`нет` остаются в характеристиках выбранного размера; точные поля `Стекло` и `Стеклопакет` по-прежнему учитываются.
- **Производные классификации:** `Цветовая гамма` не разделяет размеры при явно одинаковом точном `Цвет`. Аналогично диапазоны `МТ. Толщина полотна (сайт)` / `МТ. Толщина стали (сайт)` при одинаковой точной толщине. При неизвестной или неоднозначной точной характеристике конфликт классификации не игнорируется.
- **Сохранность:** отдельные GUID, фото, цены, остатки, исходные характеристики и прямые ссылки сохранены. Сторона открывания, точный цвет, материал, покрытие и другие не исключённые характеристики продолжают разделять исполнения.

## Подтверждённые локальные проверки

- **Сборка:** `npm run typecheck`, `npm run build`, `git diff --check`.
- **Unit:** 26 тестов разбора каталога, представления, вариантов и аудита; сохранность источников и запрет объединения разных исполнений.
- **API/PostgreSQL:** 17 тестов, включая одну семью «Аваллон», поиск по размеру, исходные свойства detail, отсутствие записей при чтении, права и изоляцию. Использована отдельная локальная БД `tandoor_catalog_minor_test` на порту 55432; production не затрагивался.
- **Chromium:** 21 сценарий UI на desktop/mobile, три вида, выбор размера, поиск/фильтры, detail, исходные данные, фотографии и параметры прототипа.
- **WebKit:** 20 функциональных сценариев и отдельный успешный повтор проверки параметров прототипа после устранения погрешности сериализации line-height (`20.3px` / `20.300001px`). Исправлен только тест, CSS не менялся.
- **Вся доступная локальная выгрузка:** 4661 товар, 7 типов цен, все GUID покрыты ровно один раз, исходный JSON неизменен. По РРЦ: 3898 → 3879 карточек, объединение у 19 моделей. Это не аудит актуального production-снимка из 4761 товара и не подтверждение выпуска.

- **До слияния:** убедиться, что PR направлен в `cursor/upload-invite-flow-problems-e22b`, проверки успешны и нет посторонних изменений. База подготовки: `2d0bbce35f7d8abdeb806375f066747bc085168d`; перед выпуском сверить свежий tip ветки.
- **До деплоя:** прочитать актуальное состояние только приложения Timeweb №258307 (`lk.tandoor.ru`), проверить, что автодеплой выключен и нет выполняющегося деплоя. Зафиксировать текущие SHA/deployment ID для возможного отката. При неожиданном расхождении с базой остановиться и выяснить причину.
- **Сохранность:** записать ID активного снимка, число товаров и отпечаток исходных записей read-only запросом. Не запускать импорт, миграции, расписания, обработку миниатюр или фоновые задания; не менять env, DNS, webhook и роли.

## Откат

При подтверждённой регрессии подготовить возврат на SHA, записанный перед выпуском, и запросить разрешение на отдельный откатный деплой. Не удалять снимки, не объединять записи 1С и не откатывать БД: схема и исходные данные этим исправлением не меняются.
