## 3. Реализованное поведение R3.1 (код)

| Правило | Реализация |
|---------|------------|
| Профили | `full` (по умолчанию, 8 файлов) и `distribution` (3 файла: groups, section, products) — `--profile=…` |
| Транспорт | Read-only FTP; набор путей зависит от профиля; или `--local-dir` для тестов |
| Dry-run | По умолчанию; apply только `--apply --expected-manifest-sha256` |
| Manifest | `profile` + канонический порядок файлов профиля (`path + size + sha256`); SHA различает профили |
| Стабильность | Двойное чтение FTP (apply); локальный режим — без повторного скачивания после проверки |
| Лимиты XML | 64 MiB/файл, 128 MiB/набор; sax; DOCTYPE запрещён; depth/elements/time limits |
| Базовый каталог | groups, sections, storages, price types, products (+ properties/images/sections); **пустой `<Товары/>` → VALIDATION_FAILED** |
| Строгость | Обязательные коды/имена; конфликтующие повторы `Свойство`/`Раздел` → ошибка до apply; идентичные повторы свойств дедуплицируются (last wins) |
| Коммерция | prices/stock/stock_expected → **staging**; битые ссылки / NUMERIC(18,4) overflow → **quarantine** |
| Apply block | `onec_catalog_state.apply_blocked`; COMMIT uncertain → блок до проверки runId / снятия оператором |
| `commercialReady` | **всегда false** в R3.1 (семантика не утверждена) |
| `distributionReady` | **true** после apply профиля `distribution`; **false** для `full` и до apply |
| Исчезновение SKU | Не удаляет старые версии; **блокирует apply** при падении count / потере известных кодов |
| Повтор manifest | Идемпотентен (`SKIPPED_UNCHANGED`) |
| Активная версия | Атомарное переключение `onec_catalog_state.active_version_id` |
| Клиенты | Таблицы `onec_clients` / journal **не изменяются** |

Корень иерархии: пустой `Родитель` / `КодРодителя`, `"0"` или отсутствие атрибута → `null` (не подменять на произвольный корень).

### 3.1. Профиль `distribution` (первый этап — выбор товаров)

**Цель:** сохранить устойчивый код 1С, название, группу (как передано), разделы, активность, свойства и пути изображений **без** цен, остатков, резервов и ожидаемых поступлений.

| Правило | Поведение |
|---------|-----------|
| Обязательные файлы | `groups/data.xml`, `section/data.xml`, `products/data.xml` |
| Коммерческие 5 файлов | **не читаются**; `commercialStatus=not_requested`; staging не заполняется |
| Отсутствующая группа у товара | **warning** `MISSING_GROUP_REFERENCE` (счётчики + примеры); `group_code` сохраняется; фиктивные группы **не** создаются |
| Профиль `full` | `MISSING_GROUP` остаётся **блокирующей** ошибкой |
| Отсутствующий родитель в иерархии **групп** | по-прежнему `MISSING_PARENT` → блокировка (правило не распространяется) |
| Чтение из БД | `LEFT JOIN` по группам; товар без найденной группы **не** исключается |
| Признак «Складская/Заказная» | только как переданное свойство ассортимента, не обещание наличия |
| Пути изображений | хранятся как данные; произвольные URL **не** скачиваются |

## 4. Ограничения и live-приёмка

- Production apply **не выполняется** из Cursor; требуется backup, dry-run на live FTP, review manifest SHA.
- Совпадение 8 SHA доказывает неизменность **прочитанных байтов**, не единую бизнес-версию 1С.
- Модель↔SKU, валюта, НДС, смысл `Доступно`, приоритет источников — **открыты** (Q12–Q17).
- Синтетика в repo **не заменяет** live-приёмку полного снимка.
