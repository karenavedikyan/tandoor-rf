## Pre-pilot setup (production)

Выполняет **admin**, не Cloud Agent:

- [ ] Подтверждены связи user ↔ employee_id 1С для участников пилота.
- [ ] Настроены команды РОП (`rop_team_members`) без mass grant.
- [ ] Региональные grants — только явные, по одному клиенту.
- [ ] Замещения — через `/api/access`, с business approval.
- [ ] **Не** выполнять mass grant all_clients в production.
- [ ] Runbook импорта согласован; расписание TW cron **не включено** до sign-off.
- [ ] Dry-run + apply smoke на staging/test DB выполнен оператором.
- [ ] Диагностика GUID (#15) при необходимости — one-shot job, не импорт.

## Предлагаемый состав пилота (v1.1)

- 1 РОП + 2–3 менеджера; региональный — при готовых назначениях.
- Данные: 8 полей JSON + `last_imported_at`; расширенная карточка — после R1.2.

**Запрещено в пилоте:**

- Объявлять плоскую запись юрлицом/ТТ.
- Выдавать региональному доступ без проверенного grant.
- Снимать server-side scope или `requireAdmin` с clients API.

## Критерии «можно начинать ограниченный пилот»

1. PR R1.5 merged; миграции `006`, `007`, `008` применены по плану (не агентом).
2. Внешний планировщик TW для `onec-scheduled-exchange` **проверен оператором** (до sign-off — ручной CLI).
3. Последний успешный `onec_client_import_runs` (mode `apply`) не старше согласованного SLA.
4. ACC-01…05, ACC-20…21, delegation smoke — green на test DB.
5. Владелец подписал G4 (бренд) и список участников.
