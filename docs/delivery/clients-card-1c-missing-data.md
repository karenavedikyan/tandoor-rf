# Карточка клиента v3: пробелы данных 1С (этап 1)

Краткий список полей и блоков прототипа [lktandoor.pplx.app](https://lktandoor.pplx.app), которых **нет** в подтверждённом обмене Exchange v3 на проде или они не связаны с карточкой ЛК. Уже описанные в контракте v3 и отображаемые в карточке поля сюда не входят.

## Обзор и KPI

| Блок прототипа | Статус | Комментарий |
|----------------|--------|-------------|
| План / факт / % выполнения | Нет в 1С v3 | Вкладка «План» — честная заглушка; источник продаж не подключён |
| Отгрузки, просрочка, рекламации (сводные KPI) | Не в v3 detail | Рекламации — Битрикс24, не обмен v3 |
| Связь юрлицо → ТТ по GUID договора | Частично | Состав только через `guid_holding`; отдельной связи legal↔outlet в v3 нет |

## Юридические лица, реквизиты, договоры

| Поле / блок | JSON / хранение | Карточка v3 |
|-------------|-----------------|-------------|
| ИНН, КПП, банк, РС, БИК, корр. счёт | Не в fixtures v3; в прототипе — planned | Только если попали в `other_fields` юрлица |
| Договор (номер, дата, статус, отсрочка, лимит) | Не в `onec_v3_*` detail | Не показываем; вкладка «Документы» — заглушка |
| «ТОП-категория холдинга» как enum | Не подтверждено в v3 | Используем `type_category.name_category` / `name_type` |

## Торговая точка

| Поле | JSON | Карточка v3 |
|------|------|-------------|
| LPR, Club, доставка, приёмка | `LPR_information`, `additional_information`, `address`, `information_loading` | Показ при наличии в БД |
| Скидки/наценки на уровне ТТ | В v3 на юрлице (`Discount`, `markups`) | На ТТ — «Не передано из 1С», если нет в snapshot |

## Вкладки без 1С (интеграции ЛК)

| Вкладка | Источник в ЛК | Сейчас |
|---------|---------------|--------|
| Работа | Битрикс24 / «Моя работа» | Заглушка, без задач |
| Витрина | Каталог R3 | Заглушка |
| Заказы | 1С / ERP (не v3 list) | Заглушка |
| Финансы | 1С задолженность (не в v3 detail) | Заглушка |
| Документы | Файлы / 1С | Заглушка |
| Рекламации | Битrix24 + `#орк` | Заглушка |
| План | План продаж (не в v3) | Заглушка |

## Ответственные

Имена и GUID менеджеров — из `managers` JSONB (ключи `guid_*` / `name_*` обмена). Если GUID пустой, показываем «Не назначен в 1С» без подстановки по ФИО.
