# Карточка v3: пробелы данных 1С (только этап «карточка»)

Сверка прототипа [lktandoor.pplx.app](https://lktandoor.pplx.app) с **подтверждённым** контрактом Exchange v3 и тем, что реально попадает в `onec_v3_*` на стенде. Не претендуем на полноту prod без свежей выгрузки.

## Уже в v3 detail (показываем при наличии в БД)

| Блок | Источник |
|------|----------|
| Тип/категория, менеджеры (имя+GUID) | `type_category`, `managers` |
| Скидка, сумма, наценки | `discount`, `discount_amount`, `markups` (юрлицо) |
| Адрес, телефоны юрлица | `address`, `telephone` |
| ТТ: адреса, маршрут, приёмка, контакты | `address`, `information_loading`, `contact_information` |
| ЛПР, Club | `lpr_information`, `additional_information` |
| Прочие поля контракта | `other_fields` — ключи из whitelist импорта (`src/onec-exchange-v3/other-fields.ts`): код, ОГРН, строки «Основной договор/соглашение», лимиты и **флаги** контроля задолженности, ретро-бонус, витрины, город/регион и т.д. |

**ИНН / КПП / банк / РС / БИК:** в whitelist v3 **нет** — на карточке не показываем, даже если ключ когда-то попадёт в `other` без контракта.

**Лимиты задолженности** из `other_fields` — это настройки 1С, **не** текущая задолженность и не просрочка.

**Строки договора** (`Оптовик_ОсновнойДоговор`, `Оптовик_ОсновноеСоглашение`) — как передано текстом из 1С; **номер, дата, статус, валюта, банковские реквизиты договора** в v3 detail **не маппятся** — нужна отдельная детализация обмена, если потребуется вкладка «Документы».

## Связи

| Тема | Факт v3 |
|------|---------|
| Юрлицо ↔ ТТ | Только через `guid_holding`; блок «Доступные точки холдинга» = **пересечение** прав/назначений сессии с выбранным сотрудником и РОПом из контекста возврата, не «все ТТ клиента» |
| Состав холдинга | Отдельный запрос composition; на юрлице KPI «Юрлица» = **1** (эта запись), не число юрлиц холдинга |

В карточке ТТ `managers` описывает назначения самой точки. Ответственные родительского клиента отдельно не переданы; назначения ТТ за них не выдаются. Для полной структуры карточки нужны явные GUID-связи ТТ → юрлицо/договор, если такие связи существуют в 1С.

## Вкладки без данных v3 (честные заглушки)

| Вкладка | Что нужно согласовать |
|---------|------------------------|
| Работа | Источник задач: **1С / Bitrix24 / ЛК** (сейчас не подключено) |
| Витрина | Каталог R3 / поля витрины в обмене |
| Заказы, финансы | Оперативные документы 1С вне текущего detail DTO |
| Документы | Файлы + реквизиты договора (№, дата, статус, валюта, банк) |
| Рекламации | **Bitrix24 / ЛК** (не обмен v3) |
| План | План продаж — отдельный контур, не v3 snapshot |
