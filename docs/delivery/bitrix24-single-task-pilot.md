# Bitrix24: пилот одной задачи

Разрешённый 30.09.2026 пилот, без импорта 1С и без расписания.

- Оператор задаёт `--bitrix-user-id <id> --task-id <id>`.
- Чтение использует одновременно фильтры `RESPONSIBLE_ID` и `ID`.
- Несовпадение ID/исполнителя, лишние записи, пагинация, неполный или пустой ответ не допускают записи в кеш.
- Прежний режим без `--task-id` не меняется. Для этого пилота его не запускать.
- Подтверждения сотрудника, объекта, связи карточки, метка, TTL и серверные права остаются обязательными.
- Журнал точечного запуска содержит `task_id`; это не означает полной синхронизации задач сотрудника. Общая сводка синхронизации сотрудника не обновляется таким запуском.

## Порядок

1. Подтвердить связь сотрудника и объекта по проверенным данным, выпустить метку.
2. Создать одну согласованную тестовую задачу.
3. Ограничить `BITRIX24_PILOT_TASK_IDS` её ID, оставить `BITRIX24_PILOT_ALLOWLIST_REQUIRED=true`, установить ограниченный TTL.
4. Выполнить `node dist/cli/bitrix24-sync.js --bitrix-user-id <id> --task-id <id>` без записи.
5. При успешной привязке включить публикацию и повторить команду с `--apply`.
6. Проверить карточку и отсутствие лишних записей. Не включать расписание.

## Проверки кода

- `typecheck`, `build`: успешно.
- Unit: 260/260.
- Integration: 179/183 при соединении через Unix-сокет; четыре теста TCP-прокси не поддерживают такую строку подключения.
- Все четыре теста TCP-прокси повторно успешно выполнены на отдельной локальной тестовой БД через TCP.
- Новые проверки: точный фильтр ID+исполнитель, запрет чужого ID/исполнителя, лишних записей/страниц, невалидных ID; запись одной задачи и её получение через авторизованный HTTP-маршрут.
- Рабочая БД не используется тестами.

## Отключение

Установить `BITRIX24_CACHE_PUBLISH_ENABLED=false` и применить конфигурацию.
При необходимости отозвать пилотную связь сотрудника. Метки не переиспользовать.
