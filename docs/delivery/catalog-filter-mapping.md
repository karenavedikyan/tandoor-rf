# Соответствия фильтров каталога (R3.2 visual)

Фильтры в API и UI появляются **только** если в активном снимке каталога есть хотя бы одно свойство товара, совпадающее с явным маппингом ниже. Свойства не выводятся «по догадке» из названия товара.

Источник маппинга: `src/catalog/filter-config.ts`.

| Ключ API / UI | Подпись | Коды свойств 1С | Названия свойств 1С |
|---------------|---------|-----------------|---------------------|
| `brand` | Бренд | `brand`, `brend`, `Brand` | Бренд |
| `series` | Серия | `series`, `seriya` | Серия |
| `color` | Цвет / декор | `color`, `colour`, `decor` | Цвет, Декор, Цвет/декор, Цвет / декор |
| `coating` | Покрытие | `coating`, `pokrytie` | Покрытие |
| `opening` | Тип открывания | `opening`, `opening_type` | Тип открывания, Открывание |
| `article` | Артикул | `article`, `artikul`, `sku` | Артикул |

## Параметры запроса

- `filterBrand`, `filterSeries`, `filterColor`, `filterCoating`, `filterOpening`, `filterArticle` — **повторяющиеся** query-параметры (`filterColor=A&filterColor=B`) или одна строка на значение. Запятая внутри значения сохраняется (`filterColor=Белый%2C%20матовый`).
- Внутри одного свойства: **ИЛИ** (товар подходит, если значение совпадает с любым выбранным).
- Между разными свойствами: **И** (все активные группы фильтров должны выполняться).
- Если передан фильтр по свойству, которого нет в активном снимке, API возвращает **422** `CATALOG_FILTER_UNAVAILABLE` (не расширяет выдачу молча).
- Фасеты возвращают до 100 значений на группу; при большем числе — `totalValues` и `valuesTruncated: true`.
- Поиск/пагинация значений: `GET /catalog/facet-values?facetKey=color&facetQ=мат&facetOffset=0` (+ те же фильтры списка). Выбранные значения всегда остаются в UI для снятия.

## Ограничения на синтетических фикстурах

Минимальный distribution-набор (`buildMinimalDistributionXmlSet`) содержит только свойство «Тип товара». Фильтры brand/series/color/coating/opening/article **не показываются** до появления подтверждённых свойств в реальной выгрузке.

## Разделы

Иерархия разделов строится из `onec_catalog_sections.parent_code`. Выбор родительского раздела включает все дочерние коды без дубликатов SKU. Циклы и битые ссылки обрабатываются безопасно (`src/catalog/section-tree.ts`).
