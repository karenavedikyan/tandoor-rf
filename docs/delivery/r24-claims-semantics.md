# R2.4: публикация рекламаций по `#орк`

## Правило публикации

В DESCRIPTION задачи Bitrix24 (уже читается существующей синхронизацией):

1. Метка клиента `#LK_*` определяет привязку (как в R2.2).
2. Ровно один самостоятельный хэштег `#орк` (регистр не важен) запускает публикацию.
3. Граница токена: `#орк` не может быть префиксом другого слова (`#оркестр` отклоняется).
4. Сводка — весь текст после `#орк` до конца описания; переносы строк сохраняются.
5. Текст до `#орк`, комментарии, вложения и чек-листы в сводку не попадают.
6. Блоки `[ЛК]` не используются.

При отсутствии метки, нескольких метках или пустом тексте после `#орк` публикация запрещена; активная `#ork_sync`-сводка отзывается после успешной проверки задачи.

## Жизненный цикл

- Запись в `bitrix24_task_summary_publications` с `publication_origin = 'ork_sync'`.
- Административные сводки (`publication_origin = 'admin'`) обработчик `#орк` не изменяет и не отзывает.
- Публикация привязана к `task_cache_version` принятого снимка; устаревший sync не перезаписывает более новую запись.
- Отзыв `#ork_sync` выполняется и без `syncExecutorUserId` (CLI/dry-run); новая публикация — только при подтверждённом исполнителе-ответственном.
- При чтении (`/claims`, `/tasks`, `/api/work/tasks`) `#ork_sync` показывается только при совпадении поколения кэша и привязки.
- Смена/потеря привязки или неподтверждённый объект → отзыв только `#ork_sync`.
- `published_by_user_id` — технический исполнитель синхронизации в ЛК, не автор текста в Bitrix24.

## API и UI

- `GET /api/clients/:guid/bitrix24/claims` — только разрешённые сводки (`portal_id + task_id`).
- Истечение TTL кэша (`synced_at`) или несовпадение поколения → `state=stale_snapshot`, `count=null`, без сообщения «рекламаций нет».
- Смешанная выборка (часть сводок актуальна, часть устарела или скрыта) → `count=null`, видимые записи без утечки скрытых.
- Вкладка «Рекламации» в карточке клиента; счётчик на обзоре — уникальные доступные обращения.
- Технический статус задачи не показывается как статус решения рекламации.

## Итог синхронизации и публикации

- Ошибки публикации `#орк` (`too_long`, `unsafe_content`, `multiple_tags`, отсутствие исполнителя) → `status=partial`, `complete=false`, журнал `partial`, `orkPublishIssues>0`.
- Безопасный отзыв без метки или с пустой сводкой, а также корректный отзыв при удалённой метке — не ошибка (`status=success`).
- При отзыве существующей сводки без права на новую публикацию сохраняются `denyCode` и `parseReason` в ответе sync.

## Ограничения

- Полномочия публикации не расширяются автоматически: действуют подтверждённая привязка, область sync и существующая матрица доступа.
- Живая проверка портала вне изолированной тестовой БД не входит в автоматический прогон.
