# Runbook: визуальный каталог и фотографии (R3.2 visual)

## Назначение

Контролируемая подготовка превью изображений каталога для read-only UI. Открытие каталога в браузере **не** запускает загрузку. Импорт 1С и sync фото в production **не выполнять** без отдельного решения.

## Переменные окружения

| Переменная | Назначение |
|------------|------------|
| `CATALOG_IMAGE_SOURCE_DIR` | Локальный каталог с файлами по путям из `onec_catalog_product_images.image_path` |
| `CATALOG_IMAGE_STORAGE_DIR` | Постоянное хранилище превью (совместимо с локальным диском / Timeweb volume) |
| `CATALOG_IMAGE_MAX_BYTES` | Лимит одного файла (по умолчанию 8 MiB) |
| `CATALOG_IMAGE_MAX_PIXELS` | Лимит числа пикселей при декодировании (по умолчанию 24 Mpx) |
| `CATALOG_IMAGE_MAX_DIMENSION` | Лимит стороны исходника (по умолчанию 4096 px) |
| `CATALOG_IMAGE_PREVIEW_MAX` | Максимальная сторона WebP-превью (по умолчанию 1200 px) |
| `CATALOG_IMAGE_PROCESS_TIMEOUT_MS` | Таймаут декодирования/генерации превью (по умолчанию 10 с) |
| `CATALOG_IMAGE_SYNC_MAX_FILES` | Лимит файлов за один прогон (по умолчанию 500) |
| `CATALOG_IMAGE_SYNC_MAX_BYTES` | Лимит суммарного объёма за прогон (по умолчанию 256 MiB) |

FTP-адреса и секреты **не** передаются в браузер. Выдача — только через `GET /api/clients/:guid/catalog/media/:assetId` с проверкой прав на карточку клиента.

## CLI

```bash
# dry-run (по умолчанию) — журнал без записи
npm run onec-catalog-image-sync:local

# явная запись готовых ассетов
npm run onec-catalog-image-sync:local -- --apply
```

Миграция `022_catalog_image_assets.sql` создаёт таблицы `onec_catalog_image_assets` и `onec_catalog_image_sync_runs`.

## Поведение sync

1. Берутся **только** пути из активного снимка каталога.
2. Проверяется безопасный путь: относительный путь внутри `CATALOG_IMAGE_SOURCE_DIR`, без `..`, URL/абсолютных путей и симлинков за пределы каталога.
3. Файл читается с лимитом байт; **sharp** полностью декодирует JPEG/PNG/WebP/GIF, проверяет размеры/пиксели и генерирует WebP-превью.
4. Dry-run считает `filesPrepared` без записи в storage/БД.
5. Apply сначала пишет **неизменяемый** объект `previews/{sha256-prefix}/{sha256}.webp` (`wx`, повтор — reuse), затем upsert в `onec_catalog_image_assets` — действующий файл не перезаписывается до успешной подготовки.
6. Повторный прогон с тем же SHA256 — skip (идемпотентность).
7. Изменение содержимого по тому же пути — новый SHA256 и обновление записи только после успешной записи превью.
8. Повреждённые/неподдерживаемые файлы отклоняются без записи в БД.

## Откат

- UI продолжает работать без фото (честные заглушки).
- Удалить строки из `onec_catalog_image_assets` или очистить `CATALOG_IMAGE_STORAGE_DIR` — изображения снова недоступны, каталог остаётся читаемым.
- Отзыв прав на клиента — media endpoint возвращает 404, кеш `no-store`.

## Live-проверка

На фикстурах integration-тестов проверены API, фильтры, иерархия и безопасность путей. **Live FTP/реальные фото не проверялись** без настроенного источника.
