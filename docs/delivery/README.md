PDF не коммитятся в репозиторий; содержание перенесено в `docs/delivery/*`. При расхождении приоритет у **согласованного эталона** (прототип + v1.1), затем этих файлов, затем кода на `main`.

## Правила работы

1. **Один PR за раз** — Cursor пишет код/документацию; Computer проверяет активный PR по ID промпта.
2. **Без самовольного расширения scope** — очередь R0→R1→…→R8 не менять; упрощения и перенос только после согласования владельцем и обновления эталона, плана и промптов.
3. **Без production-действий из Cursor** — merge, deploy, миграции на prod, импорт, создание пользователей и изменение доступов — только по отдельному разрешению владельца.
4. **Без секретов и PII в Git** — пароли, токены, реальные выгрузки 1С, телефоны и адреса клиентов не коммитятся.
5. **Подтверждение фактов** — утверждения о текущей реализации сверяются с **свежим `origin/main`** (SHA фиксируется в PR и [acceptance-matrix.md](./acceptance-matrix.md)).
6. **Не повторять PR №1–7** — см. [release-plan.md](./release-plan.md#история-pr).

## Приёмка релиза (100%)

Утверждено владельцем 28.09.2026:

- Конечный продукт **на 100%** соответствует согласованной версии прототипа по **функциям, структуре и фирменному стилю**.
- Каждый релиз **полностью** выполняет свой заранее согласованный объём.
- Это **критерий приёмки**, не оценка текущей готовности и не пиксельное совпадение.
- Допустима адаптация под реальные данные и экраны **без потери функций, смысла и стиля**.
- **Не допустимы:** заглушки, демо-данные, неподключённые обязательные функции, выдаваемые за готовые.
- **Готовность одного PR ≠ готовность релиза.** Документационный PR подтверждает применимые требования, но не объявляет релиз завершённым.

Доказательство: таблица «требование/экран → реализация → тест или скриншот → результат» с SHA PR и версией эталона — см. [acceptance-matrix.md](./acceptance-matrix.md).
