# Прерванное задание 1С: восстановление и диагностика

## Что подтверждено

При предыдущей проверке непосредственно в production-БД задание `9145d07c-7056-4628-ae1c-88f34214263b`, начатое `2026-11-13T19:48:59.599Z` (22:48:59 по Москве), оставалось `running`, без результата, связанного import run и времени завершения. Количество сохранённых ручных пакетов, файлов и строк было равно нулю; активный пакет отсутствовал. Блокировка импорта никем не удерживалась. Текущий на тот момент процесс Node был запущен позже начала задания. Эти факты подтверждают потерю исходного исполнителя без восстановления статуса, но не объясняют причину перезапуска.

При последней успешной проверке API Timeweb показывал рабочую версию `6e096bb8a4ab564e49ef1d75d550e58f4c34f1fb`, приложение `active`, автодеплой выключен. Конфигурация приложения: 1 CPU, 1024 МБ RAM. В доступном журнале нет сообщения с причиной остановки. API статистики за интервал сбоя вернул единственную точку RAM до начала импорта, поэтому оснований объявлять OOM доказанным нет.

## Причина перезапуска: пока не установлена

Нужно получить причину завершения предыдущего контейнера: exit code, OOMKilled, health-check failure либо событие инфраструктуры с временем. В новом контейнере нулевой счётчик `memory.events` не исключает OOM в предыдущем. Счётчик `oom_kill` без привязки к старому контейнеру и времени также недостаточен для точного вывода.

Техническая консоль Comet в этой попытке перестала отвечать на CDP-команды фокусировки и Accessibility. Список вкладок доступен, но выполнить свежую проверку cgroup/процесса/БД и безопасное изменение старого задания не удалось. После ограниченных повторов диагностика через эту консоль остановлена; production-задание в этой попытке не изменялось.

## Подготовленные исправления

- Новый ручной worker удерживает отдельную сессионную advisory lease весь цикл, включая чтение FTP. Маркер lease публикуется атомарно со статусом `running`.
- Чтение статуса не ждёт строку, удерживаемую импортом, и не завершает процесс с живой lease.
- После потери lease сохранённый атомарный пакет восстанавливает `success`, а его отсутствие даёт `WORKER_INTERRUPTED`. Ни новый импорт, ни автоматический повтор не создаются.
- Старые задания без маркера lease автоматически не завершаются. Для них есть адресная maintenance-команда с явным подтверждением остановки worker и проверкой точного времени старта.
- Соединение с неосвобождённой worker lease уничтожается, а не возвращается в pool. Lease восстановления транзакционная и освобождается при commit/rollback.
- При сверке продаж хеш каждого исходного файла вычисляется один раз, а не повторно для каждого клиента. Правила сверки не меняются.
- Успешный результат задания фиксируется в той же транзакции, что и проекция, включая «Нет изменений» и возврат к ранее загруженному пакету A→B→A. В этих случаях восстановление не зависит от того, какое задание первым создало пакет.

## Адресная процедура для старого задания

По умолчанию команда только читает состояние:

```sh
node dist/cli/onec-recover-interrupted-job.js \
  --job-id 9145d07c-7056-4628-ae1c-88f34214263b
```

Перед изменением оператор заново проверяет отсутствие исходного исполнителя во всех репликах, отсутствие активного импорта, сохранённых результатов и изменения самого задания. Отсутствие одной DB-блокировки само по себе не доказывает остановку старого worker, который мог читать FTP.

Только после такой проверки и разрешения на адресное восстановление:

```sh
node dist/cli/onec-recover-interrupted-job.js \
  --job-id 9145d07c-7056-4628-ae1c-88f34214263b \
  --expected-started-at 2026-11-13T19:48:59.599Z \
  --confirm-worker-stopped --apply
```

Команда откажется работать при занятой строке задания, живой новой lease, занятой блокировке импорта, другом времени старта, связанном legacy import run, другом источнике задания или терминальном статусе. Она не меняет бизнес-данные, не создаёт новое задание и не включает расписания. При существующем атомарном пакете восстанавливает успех, а не объявляет загрузку несохранённой.

Сейчас новая maintenance-команда ещё не установлена на рабочем сайте. Её наличие в исходниках не означает выполнение на production.
