# Тандор: детализация продаж в карточке до товаров и моделей

## Объём

- Исполнитель изменений: основной агент; параллельного редактора кода нет.
- Отдельная ветка от production commit `26753474479eb56d56ea41589d7e4a1498e9aaaf`.
- Развёртывание, миграции и импорт не выполняются в рамках подготовки.

## Пользовательский сценарий

- В «Обзоре» заметная кнопка «Смотреть детализацию», отдельно от широкой таблицы юрлиц.
- «Подробнее» у юрлица и общая кнопка открывают «Продажи» внутри той же карточки холдинга/юрлица.
- Выбор месяца и юрлица, категории с выручкой и количеством, затем реальные товары/модели из детальной выгрузки 1С.
- Поиск по наименованию/GUID, страницы по 50 уникальных GUID товаров. Одинаковый GUID с разными наименованиями не дублируется.
- URL сохраняет месяц, территорию исходного списка, юрлицо, категорию, поиск и страницу после перезагрузки. Смена месяца/юрлица сбрасывает категорию/поиск/страницу.
- На 375px товары показаны карточками. Существующие поля списка клиентов остаются без изменений.
- Прежняя финансовая сводка юрлица доступна через ссылку «Расширенная сводка по категориям с финансовыми показателями»; её API и правила видимости не меняются.

## Данные и безопасность

- Новый GET `/api/clients/v3/client-sales/detail`: entity, guid, month; необязательные legalGuid, productType, q, page. Только readChain, без ослабления employee-preview policy.
- Юрлица берутся исключительно из серверной разрешённой сводки той же карточки с учётом выбранной территории. Подстановка чужого юрлица отклоняется.
- Категории: существующие месячные агрегаты `onec_v3_legal_sales_lines`. Товары: `onec_v3_legal_sale_item_lines`, активный snapshot за месяц, только `catalog_matched=TRUE`.
- Нет присоединения торговых точек и умножения сумм. Товары агрегируются по уникальному GUID и категории в пределах выбранных юрлиц.
- Только выручка и количество: никаких новых полей себестоимости, маржи или скрытых юрлиц.
- Месячный итог не заменяется суммой товаров. При расхождении явное предупреждение; отсутствие строк не означает ноль. Итоги категории и товарной выгрузки относятся ко всей категории, а не к странице/поиску.
- Денежные суммы считаются в PostgreSQL numeric, сравнение итогов использует существующие точные decimal helpers.
- Поиск буквальный, не wildcard SQL; до 120 символов, категория до 200, страница 1–1000. Данные экранируются при HTML-выводе.
- Возвраты не вычитаются. Демонстрационные суммы в интерфейс не подмешиваются.
