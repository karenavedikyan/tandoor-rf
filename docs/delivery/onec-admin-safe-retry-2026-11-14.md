# Безопасный повтор обновления из 1С: результат реализации

Дата: 14 ноября 2026 года. Реализация подготовлена локально в ветке `computer/onec-admin-safe-retry` от `de6040189a6dd59f4814f04e301830813f1083ab`; на рабочий сайт не выпущена.

## Что изменилось

- **Проверка состояния:** отдельная кнопка запрашивает серверный статус и безопасную сверку, не создаёт импорт и не читает FTP заново.
- **Повтор после сбоя:** после подтверждённой ошибки появляется «Повторить обновление». Администратор подтверждает повторное чтение актуального полного комплекта из 12 файлов; новая попытка связана с предыдущей.
- **Защита запуска:** ключ запроса и серверная блокировка предотвращают дубли при повторной отправке. Неактуальная ссылка на предыдущую попытку отклоняется; работающий импорт нельзя сбросить кнопкой.
- **Неопределённое сохранение:** повтор остаётся запрещённым до освобождения блокировок и сверки атомарного результата самой попытки. Успех не заменяется ошибкой из-за потери ответа на COMMIT; сверка не активирует старый пакет поверх нового.
- **История:** администратору доступны последние 20 попыток, их идентификаторы, связь повторов, инициатор, время, результат и диагностические коды. История экранируется при отображении.
- **Интерфейс:** запуск недоступен до получения достоверного статуса. При обрыве связи повторяется чтение статуса, а не импорт; после клика сразу показывается отправка нового запроса.

Автоматические повторы и расписания не добавлены. Правила сохранения исходных строк, красных замечаний и доступа к клиентским данным сохранены.

## Проверки

| Проверка | Результат |
|---|---|
| TypeScript, сборка, `git diff --check` | Успешно |
| Полный существующий unit-набор с отдельной test-БД | 1445 пройдено, 0 ошибок |
| Дополнительный unit-тест опроса во время сверки | 1 пройден, 0 ошибок |
| Интеграционные проверки владения, восстановления и повторов | 21 пройдено, 0 ошибок |
| Браузерные проверки интерфейса с подменой API | 8 пройдено, 0 ошибок |
| Браузер + локальный сервер + PostgreSQL, без подмены API | 4 пройдено, 0 ошибок |
| Расширенный интеграционный прогон четырёх наборов | 46 пройдено, 17 ошибок |

Все 17 падений расширенного прогона воспроизведены в соответствующих старых admin/nightly-наборах на исходном коммите `de6040189a6dd59f4814f04e301830813f1083ab`, в отдельном worktree и другой test-БД. Списки упавших тестов совпали; расширенный прогон не объявляется полностью успешным.

Проверены конкурирующие запросы, повтор одного ключа после завершения, запрет устаревшего повтора, активная lease, занятая строка задания, запрет записи возобновившимся старым исполнителем, права менеджера и CSRF. Проверки COMMIT включают «Нет изменений» и повторное применение ранее встречавшегося комплекта A → B → A, а также сохранение более нового активного пакета при поздней сверке.

Потеря ответа COMMIT проверялась контролируемыми тестовыми сбоями до и после реального COMMIT в изолированной БД. Это не испытание физического сетевого обрыва PostgreSQL и не намеренная остановка рабочего приложения.

## Выпуск

Для выпуска потребуется миграция `084_onec_admin_retry.sql`: два nullable UUID-поля в журнале заданий и уникальный индекс ключа запроса. Миграция не объединяет карточки и не переписывает бизнес-данные.

PR, слияние, production-деплой, production-миграция и новый импорт в рамках этой реализации не выполнялись. После отдельного согласования выпуска нужна проверка нового интерфейса в рабочем ЛК; запуск новой загрузки требует отдельного разрешения.
